Learning to rank added a learned ordering layer

⏱ 9:05:30 · 2 min — Two stages: a cheap filter that must not miss, a learned ranker that orders. Trace the two columns, then the last line: a reranker cannot rescue what the first stage dropped.

⏱ 9:07:30 · 1½ min — Labels decide what the model can learn. Read the training-data column, not the formulas; mention that click labels carry position bias. If behind, skip the worked example.

008

Transformers in search

⏱ 9:09 · 1½ min — Cross-encoder: accurate, unsearchable. ColBERT: encode documents in advance, compare tokens at query time. Say the pattern — precompute the catalogue, keep the per-request work small.

ColBERT retains token-level matching while moving document encoding out of the query path.

009

Search became a personalized retrieval problem

⏱ 9:10:30 · 1½ min — The convergence claim made concrete: one user vector, search adds a query term. Name Alipay and BLaIR as proof at two scales. Say it holds for logged-in product search, not the public web.

Search ranks for a query q; personalization adds neural similarity between user u and document d.

010

A query is now a hypothesis about intent

⏱ 9:12 · 1½ min — A search box is a chain of predictions: what you meant, what matches, what to say. Keep hybrid retrieval in the picture — BM25 still catches exact terms. The last step opens the conversational part.

Search no longer matches a string; it predicts intent, retrieves evidence and composes an answer or ranked list of items.

011

LLM inference is constrained by memory and scheduling

⏱ 9:13:30 · 1½ min — Arithmetic, not benchmarks: 140 GB of weights, 1.25 GiB of cache per long request, one sequential step per token. Name the four mitigations and their limits. If behind, say only the three numbers.

For Llama 2 70B in BF16, one 4,096-token request adds ≈1.25 GiB of KV cache on top of ≈140 GB of weights.

012

Structure can beat parameter count on the right task

⏱ 9:15 · 1½ min — Structure over parameters on the right task: 0.6B beats 4B with the right encoder; sparse matches dense; CompresSAE gives 12× fewer parameters with a speed/exactness dial. Read the first and last row.

CompresSAE stores active coordinates and values instead of every dense coordinate; it reconstructs a dense vector when required. Kasalický et al., 2025

IV · The Cost Constraint
021

What a query costs at a hundred million users

⏱ 9:31 · 1½ min — One line of arithmetic: 1.5 billion ranking calls a day; a language model on that path is $150k a day before caching; a dot product is microseconds. Cost per request is an objective, not an ops detail.

022

Compute versus value

⏱ 9:32:30 · 1½ min — HSTU: three orders of magnitude of model complexity for 12.4%. OneRec: ten times the arithmetic, a tenth of the cost, because the cascade left the GPUs idle. Migration cost is not in either report.

In Kuaishou's accounting the saving came from using the hardware, not from a smarter model — and the migration cost is not in the report.
