The Great Convergence: Recommendation, Search, and Conversation in Real-World AI Systems

002

About my work

My perspective comes from both academic work at CTU and building recommendation technology at Recombee. The recurring question has been how systems select useful information for a person—first through prediction and recommendation, now increasingly through retrieval and generation. If time is short, omit the applied-experience row. Scale figures (over ten thousand sites and apps, over a billion recommendations a day) are public marketing numbers — verify against internal reporting before saying them aloud.

This talk benefits from research at CTU supported by Recombee - see our publications at Recombee Research.

003

How information retrieval evolved over time?

Information retrieval began as matching queries to records, then became ranking at web scale, then representation learning. In the 2020s, systems increasingly retrieve evidence and generate the response, making the system boundary harder to draw. This deck asks what should still count as IR in 2026; if short on time, skip the individual historical examples.

004

Four interfaces, one ranking problem

Show the three mock-ups in the figure and name the fourth interface in the table: an agent acting for the user, which returns at the end of the talk as the newest client of the same pipeline. Search ranks pages, recommendation ranks items, conversational retrieval ranks evidence before composing an answer, an agent ranks actions. If short on time, skip the table and use only the visual and closing line.

The interface changes; the decision remains: what should come first?

I · One job, four interfaces
005

Four lineages, one operation: rank

One slide for sixty years: each lineage added a signal it could score — term statistics, links, other people's behaviour, learned sequence context — and every one of them ends in the same operation, a sorted list. The detailed citation tables from the earlier version live here in the notes, not on the screen. If short on time, say only the last line.

Four communities optimised different interfaces and objectives — and each rebuilt the same subroutine: score candidates, sort them, learn from what was shown.

006

One implementation view: recommendation as retrieval with an implicit query

Alipay trained one search-and-recommendation foundation model on seven internal datasets: search tasks carry an explicit query, recommendation passes an empty one, and both share the user tower and the item tower. BLaIR shows the same thing at benchmark level: a single embedding table from a frozen language model serves recommendation, CF and search without retraining. If short on time, keep only the table and the last line.

The profile is the query. Alipay is an existence proof, not a theorem: exposure bias, freshness and business constraints still enter on the recommendation side.

007

What converged, and what did not

This replaces three history slides and one invented percentage from the previous version. The claim the literature supports is narrower and stronger: what merged is the machinery — vectors, contrastive training, transformers — and what did not merge is what the machinery is for and what it costs. Pinterest says it in one sentence in the UniPinRec paper. If short on time, read the two column headers and the quote.

"The backbone architecture has converged; the computational regimes remain distinct." — Pinterest, 2026

008

The shared stack in one picture

Anna opens a learning platform: she searches, gets a homepage, asks the assistant a question. All three calls hit the same catalogue, the same encoders, the same candidate generator and the same ranker; only the request and the constraints differ. This is the operational model the audience needs before any mechanism. If short on time, this slide is the one to keep from section I.

Three products, one pipeline — and three different objectives sitting on top of it. The rest of this talk walks down that pipeline and asks what it costs and what it gets wrong.

II · How the walls came down
010

Similarity became a dot product

The mechanism that made convergence possible: move the model work off the request path. A cross-encoder reads query and document together and is unsearchable at scale; a siamese encoder maps each text to a vector, so the catalogue is encoded once and a request costs one encoding plus nearest-neighbour search. Recommenders had shaped their systems this way since matrix factorization — search arrived at the same shape through DPR. If short on time, keep the table.

Move most model work offline. The online path becomes request encoding, nearest-neighbour search, ranking and constraints.

011

One encoder, three indexes

For an information-systems audience this is the practical consequence of convergence: the representation is fixed by one pretrained encoder, and the retrieval data structure — inverted index, vector index, late interaction — is chosen for the deployment. SPLADE is the striking case: a sparse, Lucene-compatible retriever that slightly beats the dense one trained from the same backbone. If short on time, read only the last two rows.

The backbone may be shared; the index decides what is cheap to retrieve and which errors dominate — missed paraphrases for lexical, missed exact terms for dense.

012

Sequences: the NLP toolkit crossed over

Each row transplants the sequence-modelling blocks from language modelling with item identifiers in place of words; what changed is the data-generating process and the objective — implicit feedback, exposure bias, a non-stationary vocabulary. Meta's HSTU closes the loop by showing that the scaling law of language models holds for recommendation once the task is written as sequence transduction. If short on time, read the first and the last row.

"Actions speak louder than words" — and they are modelled with the same machine.

013

Product and site search borrow recommender machinery

Three scales of the same statement: a benchmark, a payments super-app and a visual discovery platform all put search and recommendation on one representation. The numbers worth quoting are Pinterest's, because they are about serving, not accuracy: a foundation model was affordable only after a kernel gave six times the throughput. If short on time, keep the Pinterest row and the closing line.

In logged-in commerce, news and super-apps, search is a recommender with a query attached. Public web search is a different, more constrained animal.

014

RAG is retrieval and ranking with a writer at the end

For this audience RAG is best introduced as the pipeline they already saw, with one extra stage: a language model writes a sentence about the top-ranked items. The four fusion styles matter because they are the affordability knob — query-based fusion is the one everyone starts with and the most expensive per request. If short on time, keep the figure and the last line.

The most controllable place to choose evidence is retrieval and reranking. The generator still has to be checked for faithfulness.

015

Items become tokens: semantic IDs and constrained decoding

This is the slide that connects to the other keynotes: Klímek's structured, machine-readable catalogue is the precondition, and Mannaert's guard rails for generation have an exact counterpart here — constrained decoding makes it impossible for the model to name an item that does not exist. Semantic IDs are also why generative retrieval handles cold start: an item's identifier is computed from its content. If short on time, keep the four steps and the last line.

Guard rails for generation are not a policy document. They are a trie.

016

Conversation ranks items too

The cleanest production evidence that conversational recommendation is ranking: the model receives an instruction and a long-term user embedding as a soft prompt, and decodes semantic IDs — catalogue items — in order. The metric Spotify optimised is discovery of shows the listener does not already follow. If short on time, read the two percentages and the last line.

The interface is a sentence. The output is still a ranked list of catalogue items.

017

Some cascades are being compressed into one model

The production convergence in three rows. OneRec is the headline because of the cost line: an end-to-end generative model at ten times the FLOPs of the cascade, yet 10.6 % of its operating expense, because a single model uses the hardware — the report gives 23.7 % and 28.8 % model-FLOPs utilisation in training and inference. Pinterest kept its funnel and unified two stages; the offline lift shrank tenfold online but latency and throughput improved, which is what shipped it. If short on time, read only the last column. Bridge to the next section: once four interfaces share one stack, user control has to move from interface tricks into the representation itself — which is where steering by language comes in.

Same stack, now also for search. Most production systems still run a cascade — but notice which numbers got these three deployed.

III · Steering by language
018

You cannot edit your own vector

The gap the thesis addresses: controllable recommendation existed at the interface level — rules, prompts, instructions, critiquing — while the collaborative-filtering user embedding itself stayed untouched. Jaroslav Hradil's thesis, supervised by Rodrigo Alves in our lab with Recombee compute, gives one concrete way to steer that representation with language, evaluated offline across four backbones. Do not claim priority from the stage. If short on time, read the last row and the quote.

Existing controls sit outside the learned user representation. The question: can a sentence edit that representation directly?

019

Unfold the vector: sparse autoencoders make a profile legible

Two ideas from the language-model world, transplanted: sparse autoencoders were built to read the internals of LLMs; here they read the internals of a collaborative filter. Nothing in the backbone is retrained. If short on time, say only step three.

A tool from LLM interpretability, borrowed to make a recommender's memory readable.

020

Say it: a sentence becomes a direction in that space

This is where the convergence thesis appears inside our own work: the recommender is steered by the machinery of semantic search — a text embedder, a contrastive objective, synthetic queries — pointed at the user embedding instead of at documents. The α knob is what a product would expose as a slider. If short on time, keep steps three and four.

The steering request is literally a search query — the training prompt begins "You are a search-query writer".

021

Offline probe: language moves the ranking on four backbones, most on ELSA

Two datasets, four backbones, every configuration improved. The limits belong on the slide as spoken: offline only, no user study, only additive requests — "less action movies" is not handled yet — the probe credits only the exact item, and the requests are paraphrases about known items. ELSA, our linear autoencoder from 2022, is the strongest backbone on news. If short on time, read the ELSA row and the controls.

Moderate steering enriches the profile with the topic; full steering overwrites it. The dial matters.

IV · Grounding
022

Where hallucination comes from, and how retrieval closes it

For an information-systems audience the useful reframing is ownership: most hallucinations in retrieval-augmented systems are attributable to the retrieval and ranking stages the audience already understands, not to the generator. That also says what to measure — groundedness of the answer in the evidence — and where to fix it. If short on time, read the first row and the last line.

A conversational system that hallucinates often has a ranking problem wearing a language-model costume — and a generator that still needs checking.

023

Grounding by construction

The bridge to Herwig Mannaert's keynote: guard rails for generated artefacts have an exact counterpart in generative retrieval, where the decoder is restricted to a trie of valid identifiers. It converts "the model rarely invents products" into "the model cannot invent products". What it cannot do is choose well — which is why the talk turns to evaluation next. If short on time, keep the first row and the last line. Bridge: existence is not relevance. Grounding guarantees the system points at something real; the next section asks how we would know it pointed at the right thing.

Constrained decoding is the model-driven-development guard rail, applied to a catalogue.

V · Accuracy is measured wrong
024

Are we really making progress? 2019 and 2026

Two studies from the same Politecnico di Milano group, and the second one is more damning because the field had been warned. The mechanism is not fraud; it is that offline evaluation on public datasets rewards whoever tunes their own model hardest. For the audience the lesson is procedural: a strong, tuned, cheap baseline belongs in every comparison — which is also why linear models keep reappearing in this talk. If short on time, read the two bottom rows.

Seven years apart, the same finding: an untuned baseline makes any architecture look like progress.

025

The proxy ladder

The organising picture for the accuracy axis. Academic papers live on the bottom rung because it is the only one they can afford; production lives on the A/B rung because it is the only one that pays. The new middle rungs — simulators and language-model judges — are promising exactly when they are calibrated against A/B outcomes, and dangerous when they are trusted on their own. If short on time, keep the figure and the last line.

A proxy is only as good as its measured correlation with the rung above it — and that includes the A/B test.

026

What production optimises

Read the Pinterest row aloud: a fourteen-percent offline gain became a one-percent online gain, and the paper is still a success because it cut latency and raised throughput. Read the Kuaishou row: the model costs ten times the FLOPs and a tenth of the money, because a single model uses the GPUs the cascade left idle. These are the figures an academic paper does not report and an information-systems team cannot do without. If short on time, read only the last line and the Pinterest row.

Offline lift is a hypothesis. The A/B test is the shared production measurement of a chosen proxy — stay time is a proxy too. The cost column is the decision.

027

The same disease one floor down: backbone isolation

This is where our lab's work sits on the accuracy axis: not a better model, a better measurement. REEF is protocol-based — task, backbone, trainer, downstream model, evaluator are interfaces — so a claim about an encoder is a claim about the encoder. Status: thesis defended May 2026; publication in preparation. If short on time, read the problem paragraph and the last line.

2019 could not compare models. 2026 cannot compare encoders. Two groups answered with a framework in the same year.

028

A robust pattern: content helps most when behaviour is missing

The regularity holds from benchmarks to production: content representations are structurally the difference between something and nothing at cold start, and collaborative signal wins as soon as history exists. REEF adds the nuance that the winning modality depends on what carries preference in the catalogue — titles for films, images for clothes. The next section is about paying for both. If short on time, read the first two rows.

Content encoders give a semantic prior; interactions give behaviour. A pattern across these papers and our own results, not a law — and a system should know which one it is missing.

VI · Affordability
029

What a query costs at a hundred million users

The affordability axis in one arithmetic sentence. The Kuaishou envelope is quoted from their own report: recommenders "are often constrained to operate at a low scale and are not computation-intensive" because of QPS and latency. In our own taxonomy of objectives, cost efficiency and sub-100-millisecond response are goals of the learning problem, not something the infrastructure team fixes later. If short on time, read the first row and the last line.

Cost per request is a learning objective, not an operations detail.

030

Compute versus value

Both papers claim a scaling law; the difference is in the fine print. Economic intuition, not from the paper: a platform with billions of users can afford a thousandfold model complexity for twelve percent. Kuaishou's more interesting message for this audience is systemic: fragmenting the work into four stages wasted the accelerators, and a single model at ten times the FLOPs cost a tenth as much to run. Neither paper reports the migration cost of rebuilding the stack, and nobody has. If short on time, read the last row.

In Kuaishou's accounting the saving came from using the hardware, not from a smarter model — and the migration cost is not in the report.

031

Four serving levers

Every row is a systems contribution that unlocked a modelling result. The pattern for an information-systems audience: the user's history is the expensive part of every request, so cache it, share it between stages, and never encode it twice. If short on time, read the first and the last row.

At scale a modelling win is realised only together with a serving win. Read the systems section of these papers first.

032

Structure can beat parameter count on the right task

The affordability answer that does not require a trillion parameters: give the model the right structure. Pinterest's result is the sharpest — semantic IDs are a modality and want an encoder, exactly as images do in multimodal LLMs — and CompresSAE is our version of the same idea for retrieval: sparsity as a design decision, with a latency-versus-quality dial at run time. If short on time, read the first and the last row.

"Dense embeddings are a convenient default, but at scale they become one of the most expensive parts." — Recombee Labs, 2025 research retrospective

033

Linear models are not dead

The line from the reproducibility slide to our lab: the methods that kept beating neural recommenders in 2019 were linear, and the reason nobody deployed the best of them was a quadratic matrix. ELSA — Vančura, Alves, Kasalický and Kordík, RecSys 2022 — factorises that layer, scales linearly in the catalogue and is more accurate, not merely cheaper. "It is quite difficult to overfit training data with linear models." If short on time, read the cost row and the last line.

Keep a strong linear baseline. This is what happens when somebody does that honestly for three years: the embarrassing baseline becomes infrastructure.

034

beeFormer: interaction data inside the text encoder

The mechanism behind the "semantic is not behavioural" slide, from our side: NoteLLM at Xiaohongshu and Recformer do the same thing with a large language model; beeFormer does it with a small sentence encoder and a linear loss, which is the affordable way. If short on time, keep the figure and the last line.

ELSA stopped being only a model. It became a loss function you can use to train something else entirely.

035

In our REEF protocol, the strongest objective was the 2022 linear loss

Tomáš Laurin's thesis, defended May 2026, generalises beeFormer to text plus image with a frozen backbone, low-rank adapters and a learned per-item fusion, and finds that the ELSA reconstruction loss aligns the embedding geometry with collaborative behaviour while keeping enough semantic structure for cold start. State the failures too: the transfer columns are floor-to-floor, and the thesis says so. This is the affordability answer — you do not need 1.5 trillion parameters, you need a frozen backbone, LoRA and the right objective. If short on time, read the table and the last line. Bridge: the cheaper and more unified the stack becomes, the more power one ranking decision has — which turns control, safety, exposure and audit into first-class requirements. That is the next section.

In 2024 we put interaction data inside the text encoder. In 2026 we generalised it to images — and the best way to do it is still the linear loss from 2022.

VII · Alignment for an engineer
036

Alignment is a table of measurable properties

The definition the annotation asked for — alignment for an engineer — as a table rather than a philosophy. Each row is unpacked on the following slides, and each has a paper from our lab or from the literature behind it. If short on time, read the property column only.

Every row is engineering: a number to move, a component that moves it.

037

Convergence merges vulnerabilities: SHIELD

Our own evidence that convergence is not free: the moment search became semantic, the keyword blocklists that had protected marketplaces for a decade stopped working. SHIELD builds the training data hierarchically, filters it with a reward model and trains a small classifier that sits in the moderation layer. Presented at UMAP 2025 in New York; blog post on recombee.com. If short on time, read the two example queries and the 98.4 %.

Merge the stacks and you merge the attack surface. The fix has to understand meaning as well as the search does.

038

Exposure and the feedback loop

The alignment topic an information-systems audience can act on: exposure is a resource the system allocates, and a floor on it is a constraint you can enforce at re-ranking time — Recombee's minimum-exposure work does exactly that for multi-supplier catalogues. The thesis result on minority users is the one to say aloud. If short on time, read the first and the last row.

Bias is not a property of the data. It is a property of the loop the system closes on itself.

039

Evaluation is alignment: judges need behavioural alignment too

The bridge between the accuracy and alignment axes: the tools that promise to replace offline metrics — language-model judges, agent simulators — have to be aligned to observed behaviour and validated against A/B outcomes before they are allowed to rank models. The failure mode has a name now, which makes it easier to ask a vendor about. If short on time, read the quote and the last line.

A judge that can argue either way is not a judge. Align it to behaviour, then measure the correlation.

040

The rules outside the model

Keep this short and factual. Dates deliberately stay off the slide: check the AI Act implementation timeline for Article 50 the week of the talk and say it aloud. The point for information-systems developers: the properties the regulator names — explainable parameters, user control, transparency of generated output — are the rows of the alignment table, which means compliance is an engineering deliverable, not a legal appendix. If short on time, drop this slide entirely.

Regulation is arriving as a list of properties. The engineering table four slides ago is the same list.

VIII · The fourth interface
041

The fourth interface: the consumer of the ranking changes

The future section stays on the thesis: agents are not a new stack, they are a new client of the existing one. The commercial protocol race is context, not argument, and it dates fastest — cut it first when short on time. What matters for developers is the last row: structured, machine-readable catalogues are what agents can act on, which is Jakub Klímek's keynote seen from inside the product.

Search, recommendation, conversation — and now an agent asks the same question on the user's behalf.

042

Agents over the same stack

Our own design for an agent interface to a recommender, split into two products because the threat models differ. The design decision worth repeating to systems developers is the last line: identity is bound to the credential, so the tool has no parameter through which an agent could ask about someone else. The agent loop itself is the ranking pipeline with an execution stage; alignment properties — constraints, audit — are where the engineering effort goes. If short on time, keep the table and the last line.

The user id comes from the token, never from a parameter — an agent cannot forget to validate what it cannot pass.

043

Structured catalogue plus guard rails

A deliberate tie to the conference programme so the audience hears one story across three keynotes. Both connections are literal, not rhetorical: semantic IDs are computed from catalogue attributes, and constrained decoding is a grammar over the catalogue. If short on time, read the last line.

An agentic interface does not lower the bar for the catalogue. It is the first client that refuses to work without one.
